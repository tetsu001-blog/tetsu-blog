## MiniMax って何か。まず紹介

### サービス概要

**MiniMax** は、上海を本拠地とする**中国のAIスタートアップ**です。

扱うのは text だけじゃなく、

- 文本（文章）
- 图像（画像）
- 语音（音声）
- 视频（動画：Hailuo / H3）

という**フルモーダルのAIプラットフォーム**です。

そして2026年、日本人ユーザーにとって一番触りやすい入口が
**「MiniMax Code」** になっています。

### 主な特徴3つ

#### 1. MiniMax Code（デスクトップ＋CLI＋Web＋スマホ）

2026年9月18日、**CLI（`mcode`）が MIT ライセンスでオープンソース化**されました。

入口は3つです。

| 入口 | コマンド | 用途 |
|---|---|---|
| 対話型TUI | `mcode` | コード解読・編集・コマンド実行・テスト |
| ヘッドレス | `mcode exec` | バッチ処理、CI、pipeline |
| ACP | `mcode acp` | エディタ連携（VSCode など） |

しかも CLI は、**Anthropic 形式・OpenAI 形式の API をどちらでも受け付けます。**

つまりこういう使い方ができます。

> **「MiniMax のモデルで走らせつつ、Claude Code の画面を使う」**

これが本当に大きいです。

#### 2. M Plan（サブスク1本で全部入り）

2026年9月30日、従来の「Token Plan」から
**「M Plan」** にリネーム＆改編されました。

| プラン | 価格 | Go比 | 主な内容 |
|---|---|---|---|
| **Go** | $22/月（約3,300円） | 1倍 | テキストモデル・画像・音声・Web検索 |
| **Explore** | $55/月 | 3倍 | Go ＋ 動画モデル（H3） |
| **Build** | $132/月 | 7.5倍 | Explore ＋ ピーク時の優先アクセス |

※これは英語版の公式価格です。
中国国内向けの表示価格（¥49／¥119／¥469）は人民元建てです。
日本人は国際版（ドル建て）を利用してください。

年間契約なら、12ヶ月分で **10ヶ月分の価格** になります。

#### 3. サブスクのAPIキーが他ツールに使える（ここが神）

ここが最大のポイントです。

**M Plan の APIキー（`sk-cp-` 始まり）は、
Claude Code・Codex・Cursor・OpenCode・OpenClaw などに、そのまま差し込めます。**

つまりこういう構図が成立する。

> **「MiniMax を頭に、Claude Code で作業させる」**

Claude Code の画面やWorkflowは欲しいけど、
**モデルの頭脳部だけを差し替えて、APIコストを圧縮する。**

費用対効果の観点では、かなり強いです。

#### ⚠️ ここは絶対に注意してほしい点

この数値は、**ほぼ全部、MiniMax 自身が「自社計測・自社環境」で出したもの**です。

第三者測定（Artificial Analysis）では、
M3 の Intelligence Index は **オープンウェイトモデルの中で1位** だったものの、
絶対値は Opus 系には届いていません。

**「59.0|SWE-Bench Pro」という1つの数字に振り回して、
「全面首位だ」と太鼓判を押す風潮は危険なので、やめておいてください。**

#### しかも公式自身が「社内計測だ」と書いている

さらに決定的なのが、**M3 の公式リリースページには
「Evaluation Methodology（評価方法）」のセクションがあり、
各ベンチマークの測定条件を明記しています。**

 そこに目を通すと、**ほぼ全ての項目で "internal infrastructure"（社内環境）** と書かれています。

| ベンチマーク | 公式の記載 |
|---|---|
| SWE-Bench Verified | 自社環境で Claude Code を土台に計測（4回平均） |
| SWE-Bench Pro | 自社環境で計測 |
| Terminal-Bench 2.1 | **他3社は公式リーダーボードの値**、自社分は自社APIで計測 |
| SWE-fficiency | 「Scores from internal testing」 |
| LiveSQLBench | 「Scores from internal testing」 |
| Video-MME | *「Claude Opus 4.7 API エラー率 >20%、結果は報告せず」* |

**つまり、比較する側の数字は各社の公式リーダーボードから借り、
自分の数字だけを自分の環境で測っている** という構図です。

**これを「59.0 で Claude Opus を上回った」と書くのは、
片側だけの有利な条件下での比較** べきです。

出典：[MiniMax M3 公式リリース（Evaluation Methodology）](https://www.minimax.io/blog/minimax-m3)

そもそも、**M3 のベンチマークは「優勝した」とは書かれていない**という点も、
冷静に読むべきところです。

**ほぼ同じ水準です。甚至、少々高いくらいです。**

「中国発だから安いはず」、みたいなイメージは
**2026年の時点では通用しません。**

じゃあ、割に合わない理由は何なのか。

**「1社あたりの単価に換算すると、内容量が違う」** ということです。

Go（$22）で得られるもの、

- テキストモデル（100万トークン級の context）
- 画像生成 ＋ 音声生成
- Web検索
- デスクトップ / CLI / Web / スマホアプリ **すべて利用可**
- そして **そのAPIキーが Claude Code などに流用できる**

**これが全部入りで $22。**

API従量課金で言い換えると、
M3 は **入力 $0.30 / 出力 $1.20（100万トークンあたり）** です。

> **結論：単価は「安い」んじゃなくて、内容量が大きい。**
> **「1社あたりの内容」を重視するなら、MiniMax はかなり競争力はあります。**

### 2.5 トークン量：ぶっちゃけ「比較できない」

ここ、実は一番大事なところ。

> **「同じ $20〜22 の帯域なら、何トークンもらえるの？」**

この質問、たぶん気になるはずです。

結論から先に言います。

> **2026年10月時点、この設問は成立しません。**
> **その理由は3つある。**

#### 理由① 他社は「トークン数」を出したことがない

ChatGPT・Claude・Gemini は、
**トークン数じゃなく「メッセージ回数」か「計算量」で上限を売ります。**

| サービス | 帯域 | 上限の単位 | 公開されている数字 |
|---|---|---|---|
| **ChatGPT Plus** | $20 | メッセージ回数 | 160件 / 3時間 |
| **Claude Pro** | $20（年間 $17） | セッション＋週間 | 約45〜150件 / 5時間 |
| **Google AI Pro** | $19.99 | 計算量ベース | 具体数は非公開 |
| **MiniMax M Plan** | $22 | 相対倍率のみ | **1倍 / 3倍 / 7.5倍** |

**単位が違うので、そもそも並べることすらできません。**

#### 理由② MiniMax 自身が「絶対トークン数」をやめた

これが今回いちばん大きなニュースです。

**旧 Token Plan（2026年9月まで）は、絶対トークン数を公開していました。**

| 旧 Token Plan | 月額 | M3 の月間トークン |
|---|---|---|
| Plus | $20 | **約17億トークン** |
| Max | $50 | 約51億トークン |
| Ultra | $120 | 約98億トークン |

「$20 で月17億トークン」は、当時のニュースで繰り返し挙がった数字です。

**しかし、2026年9月30日の M Plan 移行で、この絶対数は消えました。**
公開されているのは「Go の 1倍 / Explore の 3倍 / Build の 7.5倍」だけです。

つまり **「Go が何トークンなのか」は 公式でも公開されていない。**
「何倍か」は分かるけど「何個」かは分からない、という状態です。

> **つまり、MiniMax も同じ側に回った、というのが正直なところです。**

#### 理由③ Build プランは「12倍」と「7.5倍」で食い違う

これは外部から指摘されているポイントです。

**同じ Build プランに対して、
中国公式サイトでは 12倍、国際公式サイトでは 7.5倍** と書かれています。

どちらが正しいのかは公開されていません。

少なくとも、**開示の姿勢が揃っていない** のは事実です。

### では、実際に強みはどこにあるのか

トークン量の比較はできません。

でも、**戦える軸はちゃんと残っています。**

#### 勝ってる部分：コンテキスト長

| サービス | 帯域 | 標準モデルのコンテキスト |
|---|---|---|
| ChatGPT Plus | $20 | **256K** |
| Claude Pro | $20 | 1M |
| Google AI Pro | $19.99 | 1M |
| **MiniMax Go** | **$22** | **1M** |

**同じ $20 帯で、context が 4分の1 なのは ChatGPT Plus だけです。**

長いログや多数のファイルを丸投げするなら，
ここは MiniMax / Claude / Gemini が并列トップです。

#### 勝ってる部分：モーダルの一括と、キー流用

| 観点        | MiniMax      | ChatGPT | Claude | Gemini |
| --------- | ------------ | ------- | ------ | ------ |
| 画像生成      | 〇            | 〇       | ✕      | 〇      |
| 音声        | 〇            | 〇       | ✕      | 〇      |
| 動画        | H3（Explore〜） | ✕       | ✕      | Veo    |
| 他ツールにキー流用 | **あり**       | 限定的     | 限定的    | 限定的    |

そして、枠を使い切った後も
**クレジットパック（1,000クレジット＝国際版 $1）を買える。**

これが「枠切れのペナルティが軽い」という点です。

#### 負けてる部分：短期枠の長さ

| サービス | 短期枠 | 週次枠 |
|---|---|---|
| **ChatGPT Plus** | **3時間** | あり（Thinking は 3,000件/週） |
| Claude Pro | 5時間 | あり（全モデル共通） |
| Gemini | 5時間 | あり（超えると小さいモデルに降格） |
| MiniMax Go | 5時間 | あり |

**2026年時点で、4社とも「短期枠＋週次枠」の二段構えです。**

「週次枠がないから有利」という理屈にはなりません。

**違うのは短期枠の長さだけです。**

ChatGPT は3時間で戻ります。
他の3社は5時間です。

朝のうちにまとめて処理した勢いで使っても、
**ChatGPT なら昼には戻っている**、という差です。

もうひとつ、M Plan では明記されているのに
他社は公开发していないのが、**繰り越しが不可能** という点です。

> **つまり、不利は「週次制限」（全員共通）ではなく、
> 「短期枠が5時間」と「繰り越し不可」**　です。

### 結論：トークン量で優位か？

| 比較軸 | 判定 |
|---|---|
| 絶対トークン量 | **比較不能**（そもそも誰も公開していない） |
| context 長 | **MiniMax 優位**（ChatGPT Plus のみ 256K） |
| モーダルの一括 | **MiniMax 優位** |
| 短期枠の長さ | **不利**（ChatGPT 3時間 / 他 5時間） |
| 週次枠 | 同じ（4社ともあり） |
| 繰り越し | **不利**（M Plan は繰り越し不可） |

正確な言い方だと、こうなります。

**「$20 で月17億トークン」は、2026年9月で壊された都市伝説です。**

> **「絶対量は公開されない。
> でも context とマルチモーダルでは本当に強い。
> ただし短期枠が5時間なのは少し短い。」**

### 3. 日本語体験：ここが最大の弱点

### 4. データとプライバシー：中国企業であるということ

ここは **見落としやすいけど、触れないでほしいポイント** です。

ChatGPT・Claude・Gemini はいずれも日本向けのサービスなので利用に慣れて いますが、
**MiniMax は中国発の企業です。**

ケースを分けると、

- **ブログ記事や公開情報** → **全く問題なし**

- **自分のデータ** → 自分で判断する

- **社内の機密情報／顧客データ** → これは**別のサービスを選ぶべき**です。
  ※中国内のデータ規制の影響を受ける可能性があります。

- **そもそも自前で動かしたい場合** → M3 はオープンウェイトなので、
  **自分のサーバーやローカル環境に置いて運用する** こともできます。

逆に言えば、**M3 がオープンウェイトであること自体に、実用的な意義があります。**

**自分で動かせる**のは、閉源モデルには原理的にできない交渉です。

## 実際に使ってみた感想

### 良かった点

- **100万トークンの context は本物だった**
  → 大きいログや多数のファイルを丸投げしても、トレースなく返ってきます

- **サブスク1本で全部入る**のは本当に助かる
  → 「画像系とAgent系で別々に課金してる」状態を解消できます

- **APIキーの流用ができる**のは Agent 派には強い
  → 「Claude Code の画面は欲しいけどコストは抑えたい」なら最適解になり得る

- **CLI が MIT でオープンソース**
  → 自分で改造したり、拡張したりできます

### イマイチな点

- **日本語UIがない**
  → 英語UIです。これで困る人はストレスになります

- **5時間の枠制限**がある（週次制限は他社と同じ）
  → **使い切ったら、枠が回復するまで待つ方式**です。
  朝のうちにまとめて使うと、昼になっても使えません

- **M Plan の改名が早すぎる**
  → Token Plan（Plus/Max/Ultra）から M Plan（Go/Explore/Build）へ、
  **2ヶ月も経たない** の入れ替え
  → 将来また変わる可能性はあります

- **中国企業のリスクは実在する**
  → 機密データを扱うなら、**別のサービス**を選んでください

- **ベンチマークは自社申告が多い**
  → 59.0 という数字 blindly 期待せず、実際の挙動で判断してください

## 結局、誰におすすめ？

### かなりおすすめ

- **Agent を長時間回すDeveloper**（コストを抑えて回したい人）
- **画像・音声・動画をまとめて1サブスクで使う人**
- **「Claude Code の画面で、MiniMax の脳を使いたい」人**
- **自前環境で動かす人**（オープンウェイトだからできる）
- **API従量課金のコストを限界まで押さえたい人**

### あまりおすすめしないケース

- **日本語UI がないと触れない人**
- **朝のうちにまとめて使う人**（短期枠5時間だと途中で止まる）
- **社内の機密データを使う人** → 別のサービスを選んでください
- **SNS発信や長文執筆が中心の仕事をしている人**

整理すると、

> **「会話の相手」として使うなら、ChatGPT・Claude・Gemini のほうが立派。**
> **「Agent を回す脳」として使うなら、MiniMax は現時点でトップクラスの選択肢の一つ。**

これが正直なところです。
